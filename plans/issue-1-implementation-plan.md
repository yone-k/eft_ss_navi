# 実装プラン: EFTスクリーンショットから現在地を表示するWindowsアプリの初期リリース

関連Issue: #1

## 目的

Escape from Tarkov（EFT）が新規生成するスクリーンショットのファイル名から現在のワールド座標とカメラ方向を取得し、ユーザーが選択して3地点で校正したローカルマップ画像上へ、最新位置と方向矢印を表示するWindows 11 x64向けデスクトップアプリを新規構築する。

アプリはゲームプロセス、ゲームメモリ、入力、ネットワークへアクセスせず、ユーザーのローカル環境だけで動作する。配布物はunpackagedかつframework-dependentのZIPとし、.NET 10 Runtime、Windows App SDK Runtime 2.4、Microsoft Visual C++ Redistributableを導入済みのWindows 11 x64で展開後に起動できる状態を初期リリースの完了条件とする。

## スコープ

### 対象

- C#、.NET 10、WinUI 3によるWindows 11 x64アプリと、UI非依存のドメインライブラリ、単体テストプロジェクトを新規作成する。
- 監視ディレクトリの初期候補設定、ユーザー選択、永続化、自動監視開始、監視先切替を実装する。
- 監視開始後の`Created`通知に含まれる新規PNGだけを対象とし、正規化フルパスと単調増加時計を使う2秒の重複排除を実装する。
- EFTスクリーンショットのファイル名全体をInvariant Cultureで解析し、撮影日・時分、`X, Y, Z`、`Qx, Qy, Qz, Qw`、ゲーム内時刻、任意の連番を取得する。
- 有限かつ非ゼロ長のクォータニオンを正規化し、Unityのワールド前方`+Z`を回転して水平前方ベクトルを求める。水平成分がゼロ長なら方向だけを無効にする。
- ユーザーが選択するPNG、JPEG、WebPのローカルマップ画像を、OSの追加画像コーデックに依存せず表示する。
- 約7000×7000pxのマップ画像に対するズーム、パン、画像全体表示を実装する。
- 複数のマッププロファイルについて、新規作成、明示選択、3地点校正、再校正、確認付き削除、ローカル保存、起動時の最終選択復元を実装する。
- 3組のEFT座標`X, Z`と画像ピクセル座標からアフィン変換を算出し、退化した入力および線形成分の行列式の絶対値が`1e-9`以下の変換を拒否する。
- プロファイル選択時および起動時復元時に、画像パス、寸法、SHA-256を校正時の情報と照合し、不一致なら校正を無効化する。
- 選択中かつ校正が有効なプロファイルだけを使い、最新位置の点と、アフィン変換の線形成分で変換した方向矢印を描画する。
- 最新の`X, Y, Z`、処理したファイル名、ユーザーが原因を判断できる状態メッセージを画面へ表示する。
- 監視先変更、プロファイル切替、選択中プロファイル削除、アプリ再起動では過去位置を復元せず、切替後または起動後の次の有効なスクリーンショットを待つ。
- `%LOCALAPPDATA%\EftSsMap\settings.json`へ監視先、プロファイル、最終選択プロファイルをJSON保存し、一時ファイル経由の置換で既存設定を保護する。
- READMEへ利用、校正、ビルド、テスト、必要ランタイム、framework-dependent ZIP作成の手順を記載する。
- 自動テスト、Windows 11 x64での手動確認、必要ランタイムを導入済みのクリーン環境で配布物起動確認を行う。

### 対象外

- 半透明、常に手前、ゲーム上のオーバーレイ。
- タスクトレイ常駐、バックグラウンド起動。
- 過去位置、移動軌跡、セッション履歴の保存または表示。
- 複数人の位置共有、ルーム、サーバー、テレメトリを含むすべてのネットワーク通信。
- EFTログを使うマップ自動判定。
- マップ画像またはマップ座標データの同梱、配布、ダウンロード。
- `Y`座標を使う階層またはフロアの自動切替。
- スクリーンショット画像内容の読取、OCR、画像認識。
- ゲームプロセス、ゲームメモリ、入力デバイス、アンチチート機構との連携。
- Windows 10、Windows on ARM、x86への対応。
- MSIX、インストーラー、Microsoft Store、自動更新、単一EXE化、GitHub Release自動作成。
- 時刻および数値方位の画面表示。
- 4地点以上による最小二乗校正、局所歪み補正。

## 技術選定

- **C# / .NET 10 / WinUI 3**: Issue #1で指定されたWindows 11 x64向けUI基盤として使用する。
- **ソリューション分割**: `EftSsMap.App`へWinUI、設定永続化、ファイル監視、画像処理・描画を配置し、`EftSsMap.Core`へファイル名解析、クォータニオン、アフィン変換、共有モデルを配置する。`EftSsMap.Core`はWinUI型と`FileSystemWatcher`へ依存させない。
- **xUnitテストプロジェクト**: `EftSsMap.Core.Tests`で純粋計算と、時刻・ファイルシステムを抽象化した監視／永続化ロジックを検証する。テストデータはファイル名文字列と合成データだけを使用する。
- **`SkiaSharp.Views.WinUI` 4.151.1**: PNG、JPEG、WebPをOS追加コーデックなしでデコードし、同一キャンバスに画像、位置点、方向矢印を描画する。表示用のズーム・パン変換と、元画像ピクセル座標で保持する校正情報を分離する。
- **`FileSystemWatcher`**: 有効な監視先の`Created`イベントとPNGフィルターだけを購読する。監視開始時点の既存ファイル列挙は行わない。
- **`System.Text.Json`と原子的な設定置換**: `%LOCALAPPDATA%\EftSsMap\settings.json`へ設定を保存する。保存時は同一ディレクトリの一時ファイルへ書き出してから置換し、読込不能または置換失敗時に既存ファイルを上書きしない。
- **unpackaged framework-dependent発行**: `WindowsPackageType=None`、`WindowsAppSDKSelfContained=false`、`SelfContained=false`、RID `win-x64`を設定し、publish出力一式をZIP化する。

## 考慮事項

- EFTの更新でファイル名形式が変わっても監視ループとアプリ全体を停止させず、解析失敗の状態表示とパーサーのテスト追加だけで追従できる境界を維持する。
- `FileSystemWatcher`の重複通知は受理時刻基準の2秒ウィンドウで抑制する。同一パスを2秒未満で削除・再作成した場合、2回目は初期リリースでは位置更新へ使わない。
- スクリーンショットはファイル名だけを使うため、ファイル内容の読取や書込み完了待機を追加しない。
- 画像のSHA-256計算はプロファイル選択時と起動時復元時に限定し、スクリーンショット通知ごとの位置更新経路では実行しない。
- 3地点アフィン変換はユーザーの地点選択誤差とマップ画像の局所的な歪みを補正しない。この限界と推奨する地点選択をUIとREADMEの両方で説明する。
- 設定読込不能時は破損した可能性のある元ファイルを自動上書きしない。ユーザーが原因と保存先を把握できる状態を表示する。
- 大きな画像のSkiaリソースはプロファイル切替時に確実に破棄し、UIスレッドを長時間占有する画像ハッシュ・デコード処理は非同期化する。描画更新だけをUIスレッドで行う。
- マップ画像の著作権と利用条件の確認はユーザー責任であり、実画像、画像由来の座標データ、生のスクリーンショットをソース管理、テスト資材、配布物へ含めない。
- 監視先とマップ画像はユーザー指定ファイルを読み取るだけとし、コピー、移動、削除、内容変更を行わない。
- 初期リリースではネットワーククライアント、テレメトリ、クラッシュ送信を依存関係にも実装にも追加しない。

## 検証方法

### 自動検証

以下のコマンドがすべて成功することを確認する。

```powershell
dotnet build EftSsMap.slnx -c Release
dotnet test EftSsMap.slnx -c Release
dotnet publish src/EftSsMap.App/EftSsMap.App.csproj -c Release -r win-x64 --self-contained false
```

単体テストおよび統合境界テストで次を確認する。

- サンプル4件から抽出したファイル名文字列から、正負を含む位置、クォータニオン、ゲーム内時刻を取得できる。
- 連番なし、複数桁連番、大文字拡張子、日付・時分の境界値を受理し、余分な対象外ファイル、壊れた数値、`NaN`、`Infinity`、ゼロ長クォータニオンを拒否する。
- 単位クォータニオンでは水平前方が`+Z`、Y軸周り+90度では`+X`、Y軸周り-90度では`-X`になる。
- 3組の非共線対応点から求めた変換が3点を指定ピクセルへ写す。
- EFT側と画像側それぞれの重複点・共線点を拒否する。
